# VibApp Android client preview

This is a native Android package using Tauri's Rust mobile entry point. It embeds
the exact Desktop/Web GUI and the existing verified Web/Wasm Worker runtime.
It does not load `www.vibapp.ai` into a WebView or run a remote website as the app.

The first Android profile is intentionally foreground-only. It can open verified
public apps with a packaged browser derivation, including the published LED clock.
It does not claim desktop daemon/background service,
local CodeAgent, P2P/RTC, or connected remote development support. Settings report
disconnected defaults and unsupported mutations fail explicitly. The bundled Store
snapshot is refreshed when building the APK; dynamic Store updates are not yet
implemented in this mobile preview.

## Build

Build prerequisites are Rust 1.98.0 + `aarch64-linux-android`, Node, JDK 21 (Android
Studio JBR is supported), Android SDK 36, NDK 28.2.13676358, and Build Tools 35.0.0.
Tauri CLI 2.11.4, Rust Tauri 2.11.5, Cargo/npm locks and Gradle 8.14.3 are pinned.
The Gradle distribution checksum is verified by the wrapper. These are product
release dependencies; historical Stage 0 toolchain contracts remain unchanged.

From the repository root, first run the existing Web GUI synchronizer after the
public registry/browser artifacts have been updated. Then:

```sh
cd artifacts/mobile
npm ci --ignore-scripts
node prepare-ui.mjs
npm test
# Set JAVA_HOME, ANDROID_HOME and NDK_HOME to installed absolute locations.
# Fetch the exact lockfile dependencies in the setup phase, then build offline:
CARGO_NET_OFFLINE=false cargo fetch --locked --manifest-path src-tauri/Cargo.toml --target aarch64-linux-android
node build-android.mjs
```

Use the exact installed Rust 1.98.0 toolchain; do not let the root historical
`rust-toolchain.toml` select a different product compiler. The release orchestrator
sets `RUSTUP_TOOLCHAIN=1.98.0-<host>` explicitly.
`build-android.mjs` bounds compilation to two jobs and a 2 GiB Gradle heap,
strips credentials/SSH agents from the child environment, captures a bounded build
log, and rejects a changed Cargo lockfile.

The build embeds `dist/` into `libvibapp_mobile.so`; both are generated artifacts.
`prepare-ui.mjs` rejects stale shared GUI files rather than silently publishing a
different mobile UI. No application runtime binding is fabricated by this target.

## Signing and release

`node ensure-preview-key.mjs` creates the private local preview key once under
`generated/client-signing/android-preview`, with directory mode 0700 and files 0600.
Back up the matching `.jks` and `.password` together. Never commit either file,
copy them into the APK, or send them to a code agent. An incomplete pair fails
instead of silently generating a replacement identity. This is separate from a
future production/Google Play signing identity.

`node sign-preview.mjs /absolute/path/to/app-universal-release-unsigned.apk`
aligns for 16 KiB pages, signs with that stable preview key, verifies signature and
alignment, and writes the APK, checksums and bounded receipt under `output/`.
The receipt explicitly does not certify source-commit identity or functional
acceptance; the release owner/independent verifier must establish those separately
before publication. Never publish the temporary `.aligned.apk`.
When rebuilding from a clean public checkout, set `VIBAPP_ANDROID_SIGNING_ROOT` to
the original private signing directory; do not copy private keys into that checkout
or create a different identity for each release.

## Provenance

The Android Gradle/Kotlin scaffold and icon transformations are generated by
`@tauri-apps/cli@2.11.4` (MIT OR Apache-2.0); the original VibApp icon remains the
input. Official framework references:

- https://v2.tauri.app/start/migrate/from-tauri-1/#preparing-for-mobile
- https://v2.tauri.app/start/prerequisites/#android
- https://v2.tauri.app/distribute/google-play/#build-apks
- https://v2.tauri.app/distribute/sign/android/

No third-party app code is loaded natively. Canonical Rust Component derivations
retain the same trusted public Registry binding, digest validation and dedicated
Worker isolation as the browser runtime.

The standalone `.github/workflows/android-build.yml` compiles the unsigned ARM64
APK from checked-in source; it does not upload signing keys or publish an unsigned
APK as an installable release. `ci-browser-deps` pins the exact MIT Trystero
packages required by the shared GUI synchronizer so CI never relies on a sibling
RoomHash checkout or globally installed npm packages. These dependencies do not
enable P2P/RTC in the mobile preview.
