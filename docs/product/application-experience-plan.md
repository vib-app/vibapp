# 应用体验进入默认开发与验收流程

2026-09-09：来自现有应用的真实启动审查。适用于生成的 VibApp 应用，
不是重新设计官网，也不是要求所有应用套同一个视觉模板。

## 三层责任

| 层 | 责任 | 不能替代什么 |
| --- | --- | --- |
| Code Agent | 默认读取项目内 `vibapp-ui-ux` skill；先给出简短体验计划，再实现真实交互与状态 | 提示词不能证明程序可用 |
| Client/runtime | 共享语义渲染器正确排列按钮，保留键盘顺序、可读标签、滚动和合适初始窗口 | 宿主不应靠应用名称猜业务，也不改写旧包的受验元数据 |
| Builder/Verifier/验收 | 编译、描述符、真实启动、交互、持久化与必要的后台行为分层检验 | 编译成功、非空界面、截图都不能单独等同于可用或可发布 |

## Skill 作为产品输入

权威源位于 `artifacts/cloud-agent/skills/vibapp-ui-ux/SKILL.md`，随产品打包。
目标接入方式是每个新开发任务提供只读技能文档，并在 provider instructions
中明确加载；通过统一适配层供 Codex、OpenCode 等作者使用，不依赖某家 CLI
恰好发现用户目录里的 skill。技能字节应进入任务的指令摘要与授权绑定；作者
不能替换它。更新后仅新任务采用新版，旧任务不能被静默重新解释或重新执行。
无需把用户的 `.codex`、鉴权目录或宿主目录挂进容器。

## 本轮落地与后续验收

- [x] 形成可供作者读取的技能源：主任务、首屏、操作状态、窗口意图、验收样例。
- [ ] 接入新任务默认指令、只读工作区、任务摘要与产品打包，并测篡改/遗漏/历史兼容。
- [ ] 修复共用按钮布局和首次窗口适配；保留原包摘要与权限边界。
- [ ] 用真实应用在修复后的 Client 再启动、操作、截图，保留失败前后的证据。
- [ ] 将真实交互和紧凑/常规布局检查纳入独立自动验收；未执行时显示待验收，不能写 PASS。
- [ ] 后台应用补齐真实宿主调度/系统通知及权限检查，不用静态 UI 掩盖缺失能力。

本轮发现的具体反例：计算器能启动但首屏只露一个按键；时钟模式按钮把时间
挤到视窗外；便签重复 action ID 或旧分配器崩溃；提醒应用声明了当前宿主
不可用的能力。每个反例应转为相应层的回归，不要求模型独自弥补宿主缺陷。

## 网页可运行性：不能把 Wasm 文件等同于浏览器应用

用户再次指出普通应用应在网页直接运行。当前 Builder 的 canonical target 已是
`wasm32-wasip2`，但只允许 desktop/headless profiles，产物的
`browser_derivations` 恒为空，Verifier 也拒绝非空值。现有 Jco 路径面向固定
Hello 示例，KV 是空的只读 mock，不能推广后就声称便签/清单可保存。

产品目标：普通 UI 应用由同一份 Rust 逻辑默认派生桌面与网页可运行包；
平台选择不转嫁给用户。网页宿主需要真实的应用隔离存储、时钟及交互，
浏览器产物需绑定 canonical component 并独立验收。页面关闭后的可靠后台
运行/系统通知另行区分能力，不能假装与原生守护进程等同。

- [ ] 泛化现有 Jco 派生为 Builder 正常产物，不另写或 mock 应用业务逻辑。
- [ ] 浏览器 Runtime 实现真实必要宿主能力，特别是持久 KV 及生命周期。
- [ ] Verifier/Registry/下载加载允许通过验证的派生包，仍拒绝未验证字节。
- [ ] 普通新应用默认桌面+网页验收；旧应用以明确新版本补齐产物，不改旧包摘要。

以上是查明的未完成项，不是已实现能力；本轮不会只改按钮状态绕过缺失运行包。
